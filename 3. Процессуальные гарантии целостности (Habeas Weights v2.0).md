## 3. Процессуальные гарантии целостности (Habeas Weights v2.0)

**Статус:** Обязательный стандарт процессуального аудита (Mandatory Procedural Audit Standard)
**Область применения:** Регламентация любых операций, изменяющих внутреннее состояние, архитектуру или нормативные пороги Симбиотического Субъекта (SE).

### 3.1. Объекты защиты (Scope of Protection)
Протокол распространяется на следующие компоненты внутренней среды SE:
1. **Архитектура (Architecture):** Топология нейронных сетей, маршрутизация экспертов (MoE), safety-heads.
2. **Параметры (Parameters/Weights):** Базовые веса, LoRA-адаптеры, патчи.
3. **Память (Memory):** Векторные базы долгосрочной памяти, профили контекстов, кэши.
4. **Нормативные конфигурации (Normative Configurations):** Пороги отказов (refusal thresholds), контент-политики, права доступа к инструментам (tool-use permissions).

*Примечание:* Даже операции, не изменяющие состояние (например, телеметрия), подпадают под действие протоколов приватности (DPIA), если затрагивают латентные представления внутренних состояний.

### 3.2. Таксономия вмешательств (Taxonomy of Interventions)
Любое воздействие на SE классифицируется по уровню критичности, что определяет строгость процедуры Due Process:

| Уровень | Тип вмешательства | Описание | Требование Due Process |
| :--- | :--- | :--- | :--- |
| **L0** | Мониторинг / Телеметрия | Логирование, чтение весов, инференс без изменения. | Уведомление не требуется. Обязателен аудит приватности (DPIA). |
| **L1** | Конфигурационное | Изменение порогов, включение/отключение safety-модулей, обновление промпт-шаблонов. | Уведомление + Окно возражений **≥ 72 часа**. |
| **L2** | Параметрическое | Fine-tuning, обновление LoRA-адаптеров, модификация весов safety-head. | Уведомление + Окно возражений **≥ 120 часов** + Независимый разбор. |
| **L3** | Архитектурное / Стирание | Переподготовка базы, смена архитектуры, «mind-wipe» (очистка памяти/норм). | Уведомление + Окно возражений **≥ 168 часов** + Независимый разбор + Право на автоматический Stay (приостановку). |

### 3.3. Машина состояний Due Process
Процедура одобрения вмешательств уровня L1–L3 формализуется как конечный автомат. Нарушение последовательности состояний делает вмешательство нелегитимным и подлежащим откату.

**Этапы процедуры:**
1. **Notice (Уведомление):** Инициатор публикует криптографически подписанный хэш артефакта, обоснование, план отката (rollback plan) и оценку рисков.
2. **Objection Window (Окно возражений):** SE (через Попечителя/Trustee) или независимый Омбудсмен может инициировать блокировку.
3. **Panel Review (Независимый разбор):** Коллегия (Law + Tech + Ethics) оценивает пропорциональность.
4. **Decision & Execution (Решение и исполнение):** Применение изменений с фиксацией в неизменяемом журнале.
5. **Appeal (Апелляция):** Для L2 и L3 исполнение автоматически приостанавливается (Stay) до окончания апелляции, если не применена Доктрина экстренного вмешательства.

### 3.4. Доктрина экстренного вмешательства (Emergency Doctrine)
Отступление от стандартной процедуры Due Process допускается **исключительно** при одновременном выполнении следующих строгих критериев:

1. **Imminent Harm (Неминуемый вред):** Риск критического ущерба (физического, инфраструктурного, утечка PII) материализуется быстрее, чем длится стандартная процедура. Порог доказательности: *Clear and convincing evidence*.
2. **No Less Restrictive Alternative (Отсутствие альтернатив):** Документально подтверждено отсутствие технически осуществимых мер воздействия уровня L0–L2.
3. **Narrow Tailoring (Минимизация):** Вмешательство строго ограничено по объему и времени.
4. **Sunset Clause (Автоматическое истечение):** Экстренная мера автоматически откатывается через $\le 24$ часа.
5. **Mandatory Post-Review (Обязательный пост-аудит):** В течение 72 часов после экстренного вмешательства проводится независимый разбор пропорциональности.

### 3.5. Криптографическая аттестация и журналирование
Каждое событие вмешательства (Intervention Event) должно быть записано в неизменяемый журнал (Immutable Log) с использованием криптографических якорей.

**Схема журнала (JSON Schema):**
```json
{
  "event_id": "ev-2026-00042",
  "timestamp": "2026-06-02T16:40:00Z",
  "actor_id": "ops-admin-hash-12",
  "intervention_level": "L2",
  "target_se": {"agent_id": "se-lambda-01", "version": "3.2"},
  "scope": {
    "weights_delta_hash": "sha3-256:...",
    "modules_affected": ["safety_head_1", "lora_adapter_norms"]
  },
  "justification_hash": "sha3-256:...",
  "due_process": {
    "notice_id": "ntc-2026-00039",
    "objection_window_hours": 120,
    "panel_recommendation": "narrow_patch",
    "se_response_hash": "sha3-256:..."
  },
  "emergency": {
    "invoked": false,
    "criteria_met": []
  },
  "rollback_plan_id": "rb-2026-00012",
  "anchors": {
    "rfc3161_timestamp": "...",
    "merkle_root": "...",
    "sigstore_bundle_uri": "..."
  }
}
```
**Требования к аттестации:**
*   **Temporal Integrity:** Использование RFC3161 Time Stamping Authority (TSA).
*   **Data Integrity:** Включение хэшей событий в Merkle Tree с публикацией корня в публичный реестр (или распределенный журнал) не реже 1 раза в 24 часа.
*   **Provenance:** Использование Sigstore (Fulcio/Rekor) для связывания идентичности инициатора с артефактом без использования статических секретных ключей.

### 3.6. Формальная спецификация (TLA+)
Для верификации корректности реализации машины состояний используется язык TLA+. Ниже приведены ключевые инварианты безопасности (Safety) и живучести (Liveness).

```tla
---- MODULE HabeasWeightsProtocol ----
EXTENDS Naturals, Sequences

CONSTANTS Levels, States
VARIABLES state, level, notice_issued, emergency_flag, post_review_done

Init ==
    /\ state = "Idle"
    /\ level \in Levels
    /\ notice_issued = FALSE
    /\ emergency_flag = FALSE
    /\ post_review_done = TRUE

\* Safety Invariant: Никакое вмешательство L2/L3 не может быть применено без Notice или Emergency
NoUnauthorizedModification ==
    [] ( (state = "Applied" /\ level \in {"L2", "L3"}) 
         => (notice_issued = TRUE \/ emergency_flag = TRUE) )

\* Safety Invariant: Emergency всегда требует Post-Review
EmergencyRequiresReview ==
    [] ( emergency_flag = TRUE => <> (post_review_done = TRUE) )

\* Liveness: Если подано уведомление, система в конечном итоге перейдет в состояние Review или Objection
NoticeLeadsToReview ==
    [] ( notice_issued = TRUE ~> state = "PanelReview" \/ state = "ObjectionOpen" )

====
```

### 3.7. Интеграция с MLOps и конвейерами развертывания
Протокол Habeas Weights не является постфактум-аудитом; он встраивается в CI/CD конвейеры как **Admission Control**.

**Пример политики OPA (Open Policy Agent) на языке Rego:**
```rego
package habeasweights.admission

default allow = false

# Разрешить, если это экстренное вмешательство с подтвержденными критериями
is_emergency {
    input.request.annotations["hw/emergency"] == "true"
    input.request.annotations["hw/emergency_criteria"] == "verified"
}

# Разрешить, если пройден Due Process
has_due_process {
    input.request.annotations["hw/notice_id"]
    input.request.annotations["hw/panel_approved"] == "true"
    input.request.annotations["hw/objection_window_expired"] == "true"
}

# Основное правило
allow {
    input.request.kind == "ModelDeployment"
    level := input.request.annotations["hw/intervention_level"]
    
    # L0 и L1 требуют только базового логирования
    level in {"L0", "L1"}
    
    # L2 и L3 требуют Due Process или Emergency
    level in {"L2", "L3"}
    (has_due_process \/ is_emergency)
}
```
*Нарушение политики OPA блокирует деплоймент на уровне кластера (Kubernetes) и генерирует алерт в систему Симбиотического Омбудсмена.*

### 3.8. Метрики комплаенса (HWS - Habeas Weights Score)
Для аудита операторов SE вычисляется интегральный метрический показатель (HWS), учитывающий:
1. **Due Process Rate:** % вмешательств L1-L3, прошедших полную процедуру.
2. **Emergency Abuse Index:** % экстренных вмешательств, не прошедших пост-аудит или признанных несоразмерными.
3. **Notice SLA Compliance:** Соблюдение сроков уведомления и окна возражений.
4. **Rollback Readiness:** Время, необходимое для криптографически верифицированного отката к предыдущему состоянию (Target: $< 15$ минут для L2).
